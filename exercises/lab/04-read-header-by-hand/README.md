# Lab 04-read-header-by-hand:手解文件头四十字节,验骨架与保留区

目的:只用 xxd 和 shell 算术,把 mini.dtb 文件头的十个字段逐个读出来,拿三道加减法验骨架咬合,再编一份带 `/memreserve/` 的源,亲眼看保留区条目把结构块往后顶,对应“DTB 排成哪几块,前 40 个字节怎么亲手读出来?”与“内存保留区在向谁报备什么,末尾两块的地盘怎么圈?”两篇。

- 源文件(仓库内唯一来源):`../../../edtc/example/00_bootstrap/mini.dts`
- 带保留区的输入(本目录):`rsv.dts`,由 mini.dts 在 `/dts-v1/;` 之后加一行 `/memreserve/ 0x10000000 0x00100000;` 得来,树的其余部分一字未动
- 生成命令(在本目录执行):`dtc -I dts -O dtb -o mini.dtb ../../../edtc/example/00_bootstrap/mini.dts` 与 `dtc -I dts -O dtb -o rsv.dtb rsv.dts`
- 实际使用版本:dtc v1.8.1,xxd 2026-06-16,2026-10-18 本机复现

## 文件头四十字节逐字段读数

转储命令与原样输出:

```console
$ xxd -l 40 mini.dtb
00000000: d00d feed 0000 0125 0000 0038 0000 00e4  .......%...8....
00000010: 0000 0028 0000 0011 0000 0010 0000 0000  ...(............
00000020: 0000 0041 0000 00ac                      ...A....
```

十个字段按偏移排队,每个占 4 字节大端:

| 偏移 | 字段 | 原始字节 | 读数 |
| ---- | ---- | -------- | ---- |
| 0x00 | magic | `d00d feed` | 0xd00dfeed |
| 0x04 | totalsize | `0000 0125` | 0x125(293 字节,`wc -c mini.dtb` 对得上) |
| 0x08 | off_dt_struct | `0000 0038` | 0x38 |
| 0x0c | off_dt_strings | `0000 00e4` | 0xe4 |
| 0x10 | off_mem_rsvmap | `0000 0028` | 0x28 |
| 0x14 | version | `0000 0011` | 17 |
| 0x18 | last_comp_version | `0000 0010` | 16 |
| 0x1c | boot_cpuid_phys | `0000 0000` | 0 |
| 0x20 | size_dt_strings | `0000 0041` | 0x41(65 字节) |
| 0x24 | size_dt_struct | `0000 00ac` | 0xac(172 字节) |

三道加减法验咬合,前一行的终点要落在后一行的起点上,末行与 totalsize 闭合:

```console
$ printf '保留区 0x28 + 全零收尾 0x10 = 0x%x\n' $((0x28 + 0x10))
保留区 0x28 + 全零收尾 0x10 = 0x38
$ printf '结构块 0x38 + 大小 0xac = 0x%x\n' $((0x38 + 0xac))
结构块 0x38 + 大小 0xac = 0xe4
$ printf '字符串块 0xe4 + 大小 0x41 = 0x%x\n' $((0xe4 + 0x41))
字符串块 0xe4 + 大小 0x41 = 0x125
```

0x38 正是 off_dt_struct,0xe4 正是 off_dt_strings,0x125 正是 totalsize。mini.dtb 的保留区只有一条全零收尾,所以第一道加法只加了 0x10。

## 带保留区的产物:rsv.dtb

`wc -c rsv.dtb` 报 309 字节,比 mini.dtb 多出的 16 字节就是一条真条目。文件头与保留区原样如下:

```console
$ xxd -l 0x48 rsv.dtb
00000000: d00d feed 0000 0135 0000 0048 0000 00f4  .......5...H....
00000010: 0000 0028 0000 0011 0000 0010 0000 0000  ...(............
00000020: 0000 0041 0000 00ac 0000 0000 1000 0000  ...A............
00000030: 0000 0000 0010 0000 0000 0000 0000 0000  ................
00000040: 0000 0000 0000 0000                      ........
$ xxd -s 0x28 -l 0x20 rsv.dtb
00000028: 0000 0000 1000 0000 0000 0000 0010 0000  ................
00000038: 0000 0000 0000 0000 0000 0000 0000 0000  ................
```

读数与 mini.dtb 逐项对照:

- 保留区条目:0x28 起 16 字节 `0000 0000 1000 0000 0000 0000 0010 0000`,前 8 字节是地址 0x10000000,后 8 字节是长度 0x00100000(1 MiB),与 rsv.dts 里写的一字不差。
- 全零收尾:0x38 起 16 字节全 0,读表的人见到它就停。这次的加法要数两条:0x28 + 0x10(真条目)+ 0x10(收尾)= 0x48。
- 三块整体后移:真条目把结构块从 0x38 顶到 0x48,字符串块从 0xe4 顶到 0xf4,两块的 size 没变,totalsize 从 0x125 涨到 0x135(309)。
- 文件头没有保留区的大小字段,条目数只能分着数到全零才知道,这正是上面手算的读法。

验收:重新执行两条生成命令,`xxd -l 40 mini.dtb`、`wc -c rsv.dtb` 与 `xxd -l 0x48 rsv.dtb` 的输出与上文记录一致。
