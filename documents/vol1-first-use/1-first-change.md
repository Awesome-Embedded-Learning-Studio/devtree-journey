# 改一个数,产物的字节动了哪里?

导读收尾的时候你亲手编过一次 `mini.dts`,293 字节的产物你也亲眼见过,开头的魔数 `d00d feed` 都能认了。那咱们把这身手艺往前推一小步:咱们不写新节点,新语法咱们也不碰,就把源码里的一个数换掉,看看产物的哪一处跟着动。

这一章的活就这一件,却能把三样东西的关系走实:你写的源文件,dtc 编出的产物,还有从产物倒回来的反编译文本。“DTS、DTB、dtc 都是什么”那篇里咱们用过反编译,就是把 DTB 倒回 DTS 文本的做法。这一章它要挑更重的担子,咱们拿它当核对产物的那双眼睛。

咱们把底子打好再动手:还是那个 293 字节的产物,咱们把编译、看字节、反编译各走一遍,认清楚你在源码里写的数住进了产物的哪里。

## 从 mini.dts 出发,把三样东西摆上桌

咱们要用的源文件还是仓库里的 [mini.dts](../../edtc/example/00_bootstrap/mini.dts),导读里咱们已经逐行读过它了。咱们的顺序是编译、看字节、反编译,咱们把三样东西各摆一遍。

动手咱们换个干净的工作目录,免得中间的产物混进仓库,目录名咱们就叫它 /tmp/vol1-ch1。下面命令里的仓库路径是咱们本机的克隆位置,你换成自己机器上的实际路径就行。工具还是导读里的 dtc 和 xxd 两位,咱们另外请了 cmp 和 sed 两位新帮手,它们露面的时候我再交代各自的活儿。

```shell
mkdir -p /tmp/vol1-ch1
cd /tmp/vol1-ch1
dtc -I dts -O dtb -o mini.dtb /home/charliechen/devtree-journey/edtc/example/00_bootstrap/mini.dts
wc -c mini.dtb
```

编译过程咱们没见到任何告警,`wc -c` 报出的字节数如下,跟你导读里编出来的产物一模一样:

```output
293 mini.dtb
```

看字节的活儿交给 xxd。它的输出每行 16 个字节,报完整个产物一共用了十九行,咱们不全贴,导读里你已经见过它的片段。咱们这里只把第 13 行请出来,等会儿咱们要拿行号对差异:

```shell
xxd mini.dtb | sed -n '13p'
```

```output
000000c0: 0001 c200 0000 0003 0000 0005 0000 003a  ...............:
```

第 13 行对应的偏移是 0xc0,咱们的主角就住在它的开头:0001 c200,四个字节拼成的大端整数,高位的字节排在前头,这个读法你在导读里认过。它的值换算过来是 115200。这个数你在源文件里见过,它就是 serial@1000 节点的 clock-frequency。你在源码里写的十进制数,进产物以后住的就是这里。

反方向的路咱们再走一遍,只筛关心的那一行:

```shell
dtc -I dtb -O dts mini.dtb | grep clock-frequency
echo $((0x1c200))
```

```output
		clock-frequency = <0x1c200>;
115200
```

反编译回来的写法成了十六进制的 0x1c200,shell 的算术式把它读回来,报出的还是 115200。到这里同一个数凑齐了三张面孔:源码里的十进制 115200,产物里的四个字节 0001 c200,反编译里的十六进制 0x1c200。三样东西的关系也立起来了:源文件是你写的,产物是 dtc 编的,反编译文本是从产物倒回来的。改动落在了源文件上,效果却住进了产物里,咱们找的对不对,反编译给咱们作证。

值的住处咱们已经亲手验过了。接下来咱们就真动手:把源码里的这个数换成另一个值,咱们再到产物里数清楚,跟着动的字节到底有几个。

咱们动手的位置还是前面建好的 /tmp/vol1-ch1,mini.dtb 与源文件的路径都照旧,cmp 和 sed 两位帮手也到了露面的时候。

## 改哪一行?咱们挑 clock-frequency

咱们挑的改动落在 serial@1000 节点,动的是 clock-frequency。导读里咱们认过它,存的是一个纯粹的数:115200 是串口通信里常见的波特率数字,波特率说的是串口每秒传输的位数。咱们换掉这个数,牵连不到树里的别的东西。9600 同样是常见的波特率数字,咱们拿它当新值。

改文件的活儿咱们交给 sed,它是个按模式改文本的流编辑器。咱们让它把 clock-frequency 的旧值换成新值,结果写进 mini-9600.dts,原文件倒是不会动:

```shell
sed 's/clock-frequency = <115200>;/clock-frequency = <9600>;/' /home/charliechen/devtree-journey/edtc/example/00_bootstrap/mini.dts > mini-9600.dts
diff /home/charliechen/devtree-journey/edtc/example/00_bootstrap/mini.dts mini-9600.dts
```

```output
11c11
< 		clock-frequency = <115200>;
---
> 		clock-frequency = <9600>;
```

diff 告诉咱们,两个文件的差别只有第 11 行,那行里的旧值 115200 换成了新值 9600。咱们改的就是一行,名副其实。接着把改过的源文件也编成产物:

```shell
dtc -I dts -O dtb -o mini-9600.dtb mini-9600.dts
wc -c mini.dtb mini-9600.dtb
```

```output
293 mini.dtb
293 mini-9600.dtb
586 total
```

## 大小没变,变的字节只有三个

两个产物的大小都是 293 字节。这个结果你细想一下就通了:新旧两个值都是 32 位整数,在产物里占的字节数相同,哪个字节都没有挪窝的必要,别的部分更没有动的理由。

光看大小咱们还不够放心,咱们请 cmp 出场。它逐字节地比较两个文件,比较的结果一行报一处不同,-l 就是让它列全的选项:

```shell
cmp -l mini.dtb mini-9600.dtb
```

```output
194   1   0
195 302  45
196   0 200
```

第一列报的是字节序号,咱们按十进制从 1 数它,后两列是两个文件各自的字节值,值用的还是八进制报数,你暂时不用换算,咱们马上有看得舒服的版本。cmp 一共报了三处,报出的序号是 194、195、196,换成从 0 起数的偏移就是 0xc1、0xc2、0xc3。

看得舒服的版本来了,咱们把两个产物的十六进制各排成一列,再让 diff 替咱们去比:

```shell
diff <(xxd mini.dtb) <(xxd mini-9600.dtb)
```

```output
13c13
< 000000c0: 0001 c200 0000 0003 0000 0005 0000 003a  ...............:
---
> 000000c0: 0000 2580 0000 0003 0000 0005 0000 003a  ..%...........:
```

diff 报的 13c13 说的就是第 13 行换了内容,正是咱们前面请出来的那一行。0001 c200 变成了 0000 2580,行尾的字符列里多了一个百分号,那是新字节 0x25 的可打印样子。值住的四个字节从 0xc0 到 0xc3,头一个字节的前后都是 00,cmp 就只报了三处,跟它报的数目对得上。至于区块怎么划分、值为什么恰好住在 0xc0,那是产物内部格式的事,第二卷讲格式的时候咱们把区块一个个认过去,这一章咱们只要守住改动与字节的对应。

## 反编译回来,那一行看得见

字节层面的证据有了,咱们再从反编译的方向核对一遍:

```shell
dtc -I dtb -O dts mini-9600.dtb
```

```dts
/dts-v1/;

/ {
	compatible = "edts,a_demo";
	#address-cells = <0x01>;
	#size-cells = <0x01>;

	serial@1000 {
		compatible = "acme,uart";
		reg = <0x1000 0x100>;
		clock-frequency = <0x2580>;
		status = "okay";
	};
};
```

结构原样回来了,serial@1000 里的 `clock-frequency` 变成了 `<0x2580>`。换算咱们还是用 shell 的算术:

```shell
echo $((0x2580))
```

```output
9600
```

正是咱们写进源码的数。同一行改动到这里就有了三个方向的对证:xxd 里值所在的字节换了内容,cmp 数出了三处不同,反编译把 0x2580 摆了回来,换算出来的 9600 分毫不差。

## 改的是描述,核对的是产物

现在咱们退后一步,看看这一行改动的身份。clock-frequency 存的是描述里的一个数,咱们这次动的也只有数据,代码的边都没沾上。可产物的字节真的换了,因为描述本身指的就是数据,数据换了,编进产物里的数据跟着换。

咱们回想“谁会使用设备树”那篇的四站:读取、修改、传递、消费。轮到消费的软件读产物的时候,它拿到的就是新描述。真实板子上的串口驱动会把这个数当输入时钟的频率去算分频,咱们的演示树里没有驱动到场,分工却是一样的:描述管说什么,消费的软件照着办。

另一个收获是核对的本事。源码改了什么,产物里就有对应的变化,大小、字节、反编译三个方向咱们都能验。往后你在真正的板子上调设备树,拿不准描述与产物对不对得上的时候,咱们有整套不靠猜的办法,xxd、cmp 和反编译就是这套办法的头三样。

这一章配了实验 [lab/01-first-change](../../exercises/lab/01-first-change/README.md),它的输入文件、生成命令与验收条件都写在里面,你照着走一遍就能复现咱们上面的全部输出。

一行改动咱们看到底了。可日常的功课不止改一个数,你要回答的问题会换一副样子:这块硬件该用哪些属性来描述,节点怎么组织,公共的部分怎么让多块板子共享。“怎样描述和组织设备”那章接的就是这个班,导读里露过脸的 .dtsi 到那里正式开工。
