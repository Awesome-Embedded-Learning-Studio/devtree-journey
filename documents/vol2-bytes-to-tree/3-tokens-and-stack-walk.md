# 树在文件里是一串记号,怎么把整棵树读回来?

“这个 DTB 文件如何布局”那章里咱们把 293 字节的 mini.dtb 从整体看过一遍:文件头里的十个字段、一段空的内存保留区,还有结构块与字符串块各自的字节范围,前 40 字节是你亲手解出来的。可结构块里住着的那一百多个字节,咱们当时只圈出了范围,其实还一个都没读过。这一篇咱们就进去:树在源码里是嵌套的,进了产物却摊平成了一串字节,咱们顺着记号走,才能把整棵树安全地读回来?

咱们这一章的次序是认记号、手工解、写遍历器、弄坏产物,本篇管前面的三步:咱们把五种记号一种一种认清楚,把 mini.dtb 开头的那几个亲手解出来,末了请栈把整棵树一口气读完,手工解码要用的本事,你在前面几章其实都练过了。

## 结构块里只认五种记号

“这个 DTB 文件如何布局”那章解文件头的时候你已经确认过:结构块的起点在 0x38,长度占了 0xac 个字节,而字符串块从 0xe4 开始,占下了 0x41 个字节。结构块的内容按规范 v0.4 第 5 章的说法是一串片段,每个片段的开头是一个大端 32 位整数,而这个数就是记号。数据跟不跟、跟多少全由记号的值说了算,v17 的格式里记号一共五种:

| 记号              | 值           | 记号后面跟的数据                                                       |
| ----------------- | ------------ | ---------------------------------------------------------------------- |
| `FDT_BEGIN_NODE`  | `0x00000001` | 节点的名字,`\0` 结尾,补零对齐到 4 字节                                |
| `FDT_END_NODE`    | `0x00000002` | 无                                                                      |
| `FDT_PROP`        | `0x00000003` | `len`、`nameoff` 两个大端 32 位数,再跟 `len` 字节的值,补零对齐到 4 字节 |
| `FDT_NOP`         | `0x00000004` | 无                                                                      |
| `FDT_END`         | `0x00000009` | 无,整个结构块只有它一个,住在最末尾                                    |

编号从 1 排到了 9,中间的号没派上用场,咱们把值背下来就好,缺口处住着谁咱们就不去猜了。带数据的只有 `FDT_BEGIN_NODE` 和 `FDT_PROP` 两种,其余三种都是孤零零的四个字节。规范还给记号的接龙立了约束:节点的名字后面、属性数据后面,接下来的记号可以是除 `FDT_END` 外的任何一种,而 `FDT_END_NODE` 后面不许再跟 `FDT_PROP`。这个限制配上另一条要求读起来就通了:一个节点的全部属性必须排在它的子节点前面,属性在节点关门的 `FDT_END_NODE` 之后就没有了落脚的地方。属性排在子节点后面的产物,dtc 读到了只会发一条告警,但是不拦,咱们在 edtc/reference/dtc 的 flattree.c 里核对过这段处理。

`FDT_NOP` 的身份是占位。咱们把一个属性或节点的记号改写成 NOP,树里就少了它,产物里的其他字节却一个都不用挪,这正是它的用处。所以遍历器读到 NOP 跳过去就行,它连一个字节的数据都不背,咱们也不用管它蹲在哪条缝里。

## 动手:开头几个记号,咱们手工解出来

咱们照旧用老办法,动手的环节搬进 /tmp 里做。目录咱们叫 /tmp/vol2ch5,下面命令里的仓库路径是咱们本机的克隆位置,你换成自己机器上的实际路径就行:

```shell
mkdir -p /tmp/vol2ch5
cd /tmp/vol2ch5
dtc -I dts -O dtb -o mini.dtb /home/charliechen/devtree-journey/edtc/example/00_bootstrap/mini.dts
xxd -s 0x38 -l 0x30 mini.dtb
```

咱们给 xxd 交代 `-s 0x38` 和 `-l 0x30` 两个选项,意思是从结构块的起点往下读三行,产物还是同一份 mini.dts 编出来的,内容跟上一章你解过的完全一样:

```output
00000038: 0000 0001 0000 0000 0000 0003 0000 000c  ................
00000048: 0000 0000 6564 7473 2c61 5f64 656d 6f00  ....edts,a_demo.
00000058: 0000 0003 0000 0004 0000 000b 0000 0001  ................
```

咱们从 0x38 起头,一个记号一个记号地读。咱们读到的头四个字节是 0000 0001,而值 1 就是 `FDT_BEGIN_NODE`,它宣布一个节点开了门。紧跟在后面的是节点的名字,咱们从 0x3c 开始找 `\0`,找到的却只有 00,所以根节点的名字是个空串,名字连同结尾符只占了 1 个字节。名字读完了还不算完,读指针要补零对齐到 4 字节的边界,0x3d、0x3e、0x3f 的三个 00 就是补出来的,所以下一个记号从 0x40 开始。

0x40 处的四个字节是 0000 0003,`FDT_PROP` 到了场,属性开始自我介绍。它后面跟着两个大端 32 位数:0x44 处的 0000 000c 说值长 12 个字节,0x48 处的 0000 0000 是 nameoff,意思是属性名住在字符串块的开头。而值本身从 0x4c 开始,占了 12 个字节:6564 7473 2c61 5f64 656d 6f00,咱们按 ASCII 读出来是 `edts,a_demo\0`,串口的身份就这么带着结尾符住进了产物。12 个字节恰好是 4 的倍数,这次就不用补零了,所以下一个记号从 0x58 开始,咱们又读到一个 0000 0003。

第二个属性正好给咱们练 nameoff。0x5c 处的 len 是 4,0x60 处的 nameoff 是 0x0b,所以属性名的开头在 0xe4 + 0x0b = 0xef,你拿后面字符串块的转储一对,那里住的就是 `#address-cells`。值占了 4 个字节,咱们在 0x64 处读到 0000 0001,正是源码里写的 `<1>`。你看到了吧,手工解码其实不需要魔法,咱们干的活就是“读记号、按记号的约束走指针”,两章攒下的本事到这里正好接上。

五种记号的样子你都见过了,开头的几个也解出来了,手工解码到这里算是走通了。不过咱们解的只是 0x38 起头的一小段,没读的字节还有一百来个,咱们怎么把整棵树一口气读完,每个节点住的路又怎么报出来,接下来咱们请栈来接活。

## BEGIN 和 END 一配对,栈就是路径

记号认完了,咱们把整条流水线想通。结构块是线性的,树是嵌套的,而中间的翻译全靠 `FDT_BEGIN_NODE` 和 `FDT_END_NODE` 的配对:咱们读到 BEGIN 就压栈,而读到 END 就弹栈,任意时刻栈里放着的,是从根到当前节点的每一层名字,栈的深度就是嵌套的深度。路径其实也不用另外记,咱们把栈里的名字用斜杠连起来就是了。走法顺着深度来:节点开了门,咱们读完它的全部属性,再一头扎进它的子节点,子节点的门关上了才轮到下一个兄弟。

咱们把上面的想法写成三十来行 Python,你存成 walk.py 就能跑:

```python
import struct
import sys

fname = sys.argv[1] if len(sys.argv) > 1 else 'mini.dtb'
data = open(fname, 'rb').read()
magic, totalsize, off_struct, off_strings = struct.unpack_from('>4I', data, 0)
size_strings, size_struct = struct.unpack_from('>2I', data, 32)
assert magic == 0xd00dfeed

stack = []      # 栈里放已打开节点的名字,栈顶就是当前路径的末端
pos = off_struct
end = off_struct + size_struct
while pos < end:
    tok = struct.unpack_from('>I', data, pos)[0]
    if tok == 1:   # BEGIN_NODE:名字是 \0 结尾串,读完对齐到 4
        name = data[pos+4:data.index(0, pos+4)].decode()
        stack.append(name)
        pos = (data.index(0, pos+4) + 1 + 3) & ~3
    elif tok == 2: # END_NODE:弹栈,BEGIN 与 END 的配对在这里兑现
        stack.pop()
        pos += 4
    elif tok == 3: # PROP:len + nameoff + len 字节的值,读完对齐到 4
        ln, nameoff = struct.unpack_from('>2I', data, pos+4)
        base = off_strings + nameoff
        pname = data[base:data.index(0, base)].decode()
        path = '/' + '/'.join(s for s in stack if s)
        print(f'{path}  {pname} = {ln} 字节')
        pos = (pos + 12 + ln + 3) & ~3
    elif tok == 4: # NOP:不带数据,跳过
        pos += 4
    elif tok == 9: # END
        pos += 4
    else:
        raise SystemExit(f'不认识的记号 0x{tok:08x},拒绝继续')

print(f'遍历结束,栈深度 {len(stack)},读指针停在 {pos:#x},结构块末端 {end:#x}')
```

咱们把它跑起来:

```shell
python3 walk.py mini.dtb
```

```output
/  compatible = 12 字节
/  #address-cells = 4 字节
/  #size-cells = 4 字节
/serial@1000  compatible = 10 字节
/serial@1000  reg = 8 字节
/serial@1000  clock-frequency = 4 字节
/serial@1000  status = 5 字节
遍历结束,栈深度 0,读指针停在 0xe4,结构块末端 0xe4
```

七条属性咱们全部对上了,栈深度归了零,读指针不多不少停在结构块的末端 0xe4。规范还留了一个自查口径:`FDT_END` 之后的头一个字节,它的偏移减去结构块的起点,应当恰好等于文件头里的 size_dt_struct,咱们的 0xe4 - 0x38 = 0xac,对上了。dtc 自己读产物时用的是递归,函数在子节点处调用了自己,C 的调用栈替它当了栈,咱们在 flattree.c 的 unflatten_tree 里核对过。

咱们还有一件旧事要在这里对上。“改一行 DTS,产物发生了什么”那章里咱们盯着 0xc0 处的四个字节看过 0001 c200,当时你只知道值是 115200,却不知道它为什么恰好住在 0xc0。现在你自己就能算了:从 0x38 起头,把每个记号占的字节数一路加过去,clock-frequency 属性的值就落在 0xc0 到 0xc3。第一卷里你信了咱们的说法,到了这一篇,你手里有了自己算出来的证据。

树读回来了,规范的自查口径对上了,压在 0xc0 上的旧事也对上了,这一篇的遍历器算是立住了。不过代码里还有两处咱们照着写了、没有细看的算式:对齐的那句 `(pos + 12 + ln + 3) & ~3`,取名字的那句从偏移找 `\0`。补零的缝和名字的仓库,咱们下一篇看个明白。
