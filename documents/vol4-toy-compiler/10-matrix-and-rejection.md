# 家底怎么摆成表,接不住的怎么说不接?

扩展的队伍上一篇排好了,能跑的代码却还没有跟上,咱们手里的玩具到底接得住什么,这一篇要把它摆成看得见的家底:一张矩阵写清支持的范围,一套测试守住拒绝的边界。

## 支持矩阵:把家底摆成一张表

能力清单靠嘴说是立不住的,咱们得立一张表。支持矩阵是 edtc 对外的能力清单:每种语法的状态占一行,写的是支持、部分支持还是不支持。部分支持的行必须把边界写清,不支持的行要挂拒绝测试。咱们给目标态画一张示范,状态列写的是里程碑走完之后的承诺,代码的现状未落地,矩阵点亮的节奏跟着里程碑走:

| 语法 | 状态 | 边界与验收 |
| ---- | ---- | ---------- |
| /dts-v1/ 头 | 支持 | 只认版本 1,别的版本拒绝 |
| 节点定义与嵌套 | 支持 | 深度与兄弟数设上限,防越界与无限递归 |
| 空属性 | 支持 | 零长度的值,产物里长度记 0 |
| 字符串与字符串列表 | 支持 | 带结尾零进产物 |
| 32 位非负 cells | 支持 | 超出 32 位即拒绝,不截断 |
| 字节串 | 支持 | 方括号的写法原样转字节 |
| 注释 | 支持 | `//` 与块注释都认 |
| 标签与 & 引用 | 排期,M5 | 悬空引用、重复标签明确失败 |
| /include/ | 排期,M6 | 词法层搬文件,-i 查找路径,位置层层回溯 |
| 节点合并 | 排期,M6 | 同路径合并,同名属性后写赢 |
| /delete-node/ 与 /delete-property/ | 排期,M6 | 删不存在的东西怎么办,跟着拒绝原则定 |
| 顶格 &label 块 | 排期,M6 靠后 | 依赖 M5 的标签到路径解析 |
| 井号指令与宏 | 预处理接入,M6 | edtc 不认,交给 cpp,输入是纯 DTS 加行标记 |
| 表达式与 /bits/ 64 | 不支持 | 明确拒绝,报错带位置与原文 |
| /incbin/ 与 overlay 语法 | 不支持 | 明确拒绝,报错带位置与原文 |

矩阵的行不是一次写死的。咱们每点亮一行,要一起交的三样材料是正常测试的夹具、错误测试的拒绝夹具,再加与上游 dtc 的对拍记录。矩阵跟着仓库的进度走,课程的实验同步更新,读者随时能看到诚实的边界。实验失败的时候,你也能立刻分清是自己的树写错了,还是碰上了矩阵里写明的拒绝项,两种处境的出路完全不同。

## 拒绝测试:接不住的时候,怎么说我不接

拒绝的手艺,参考的答案就在 dtc 身上。咱们造两个坏输入看 dtc 怎么报,头一个输入是悬空的引用,clocks 引用了一个哪儿都没定义的标签:

```dts
/dts-v1/;

/ {
	#address-cells = <1>;
	#size-cells = <1>;

	clock-controller {
		compatible = "demo,fixed-clock";
	};

	uart@1000 {
		compatible = "demo,uart";
		reg = <0x1000 0x100>;
		clocks = <&nosuch>;
	};
};
```

```shell
dtc -I dts -O dtb -o rej-undef.dtb rej-undef.dts
```

```output
rej-undef.dts:11.12-15.4: ERROR (phandle_references): /uart@1000: Reference to non-existent node or label "nosuch"

ERROR: Input tree has errors, aborting (use -f to force output)
```

咱们造的第二个坏输入是重复的标签,同一个标签挂到了两个不同的节点上:

```dts
/dts-v1/;

/ {
	clk24: clock-controller {
		compatible = "demo,fixed-clock";
	};

	clk24: other-clock {
		compatible = "demo,another-clock";
	};
};
```

```shell
dtc -I dts -O dtb -o rej-dupe-label.dtb rej-dupe-label.dts
```

```output
rej-dupe-label.dts:8.21-10.4: ERROR (duplicate_label): /other-clock: Duplicate label 'clk24' on /other-clock and /clock-controller
ERROR: Input tree has errors, aborting (use -f to force output)
```

咱们把 dtc 的报错样式分开看:位置落到了文件、行、列上,检查项有自己的名字,出错的内容原样引着,退出码报的不是 0,咱们的产物文件压根没出来。你拿到手能定位、能改,这就是体面的拒绝。

dtc 也有两处做法值得咱们掂量,咱们只参考、不照办。头一处咱们往 cell 里塞一个超过 32 位的数:

```dts
/dts-v1/;

/ {
	#address-cells = <2>;
	#size-cells = <2>;

	bus@840000000 {
		reg = <0x0 0x840000000 0x0 0x100000>;
		wide = /bits/ 64 <0x123456789abcdef0>;
	};
};
```

```shell
dtc -I dts -O dtb -o bits64.dtb bits64.dts; echo "exit=$?"
```

```output
WARNING: bits64.dts:8.14-25: Value 0x0000000840000000 truncated to 0x40000000
exit=0
```

它警告了一声,退出码还是原来的 0,产物还是照写了,高出的位没了,0x840000000 进产物变成了 0x40000000。警告拦不住带病的字节进启动链路。“构建系统实际上做了什么”那章里咱们就提防过这件事,到了自己的玩具上它就成了硬约束:子集说好的是 32 位非负,超界的数直接失败,咱们不截断、也不警告放行。

第二处咱们删一个不存在的节点:

```dts
/dts-v1/;

/ {
	#address-cells = <1>;
	#size-cells = <1>;

	uart@1000 {
		compatible = "demo,uart";
		reg = <0x1000 0x100>;
	};

	/delete-node/ nosuch@2000;
};
```

```shell
dtc -I dts -O dtb -o rej-delnode.dtb rej-delnode.dts; echo "exit=$?"
dtc -I dtb -O dts rej-delnode.dtb | grep -n 'nosuch\|uart@1000'
```

```output
exit=0
7:	uart@1000 {
```

编译通过了,咱们连一条提醒都收不到,产物里的 uart 还在,树上的 nosuch 本来就不存在,删了等于没删,dtc 对这件事的态度是一声不吭。宽容是 dtc 的选择,咱们的玩具选另一条路:删不存在的东西按错误处理,因为九成的时候它意味着你拼错了名字,静默通过等于把错误藏进了产物。

有了正反两面的参照,咱们给 edtc 定三条拒绝原则,每条都要长成锁进回归夹具的错误测试:

1. 子集外的语法一律拒绝。报错带文件、行、列,引着出错的原文,说明它属于哪一类不支持的表达,给出路,比如宏没展开就请交给 cpp。
2. 部分支持的能力把边界检查做实。越界的值直接失败,不截断、不静默改写、不警告放行。
3. 删不存在的节点、引不存在的标签,都按错误处理,哪怕参考实现宽容。

这些夹具跟正常测试一起住进了 edtc/test/,每个拒绝夹具断言的两件事:退出码给的是非 0,报错文本里找得到位置和检查项的名字。夹具的运行挂在每回提交前,谁改坏了拒绝行为,咱们让构建当场失败给他看。

矩阵立了,原则也定了,可表态还缺一遍真刀真枪的验证:真实的树喂进真实的工具链会发生什么,咱们还没当面看过。下一篇咱们拿 imx51-babbage 当试金石,两版的标本各编一回,把矩阵里的行一行一行对上真实的输入。

2. dtc 的报错样式里,咱们读出了哪几样东西?这样的拒绝好在哪?
3. cell 里塞进 0x840000000,dtc 是什么态度?咱们的玩具打算怎么做?

1. 部分支持的行要写清支持的边界,比如 cells 只认 32 位非负,超出即拒。三样材料是正常测试夹具、拒绝夹具,再加与上游 dtc 的对拍记录。
2. 位置落到了文件、行、列上,检查项有自己的名字,出错的内容原样引着,退出码报的不是 0,产物文件压根没出来。你拿到手能定位、能改,这就是体面的拒绝。
3. dtc 警告了一声,退出码还是 0,产物照写,高出的位被截掉。咱们的玩具按拒绝原则的第二条,超界的数直接失败。
